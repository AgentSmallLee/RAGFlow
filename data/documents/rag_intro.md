# RAG（检索增强生成）技术介绍

## 什么是 RAG

RAG 的全称是 Retrieval-Augmented Generation，即检索增强生成。它是一种结合了信息检索和大语言模型的技术框架，旨在提升大模型回答的准确性和时效性。

RAG 的核心思想是：在回答用户问题之前，先从外部知识库中检索出与问题相关的文档片段，然后将这些片段作为上下文一起提供给大语言模型，让模型基于检索到的信息生成回答。

## RAG 的发展历史

RAG 概念最早由 Facebook AI Research（现 Meta AI）在 2020 年的论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》中提出。最初的 RAG 主要用于开放域问答等知识密集型任务。

随着大语言模型的快速发展，特别是 ChatGPT 的出现，RAG 技术在 2023 年迎来了爆发式增长。企业开始广泛采用 RAG 来构建内部知识库问答系统，以解决大模型的知识截止问题和幻觉问题。

## RAG 的核心优势

### 1. 减少幻觉（Hallucination）
大语言模型有时会生成看似合理但实际错误的内容，这被称为"幻觉"。RAG 通过提供真实的参考资料，显著降低了模型编造事实的可能性。

### 2. 知识实时更新
大模型的训练数据有截止日期，无法获取最新信息。RAG 通过实时检索外部知识库，可以让模型基于最新的文档进行回答。

### 3. 保护数据隐私
企业的内部数据无法直接用于训练大模型。RAG 采用检索的方式，数据不需要离开企业内部环境，有效保护了数据隐私和安全。

### 4. 可解释性强
RAG 系统可以展示回答所依据的参考来源，用户可以追溯答案的出处，增强了系统的可信度。

### 5. 成本可控
相比微调（Fine-tuning）大模型，RAG 的实施成本更低，更新知识库也更简单快捷。

## RAG 的基本流程

一个完整的 RAG 系统通常包含离线建库和在线问答两个阶段。

### 离线建库阶段
1. 文档加载：读取各种格式的文档文件
2. 文本切分：将长文档切分为适合向量化的文本块（Chunk）
3. 向量化：使用 Embedding 模型将文本块转换为向量
4. 存储入库：将向量和原始文本存入向量数据库

### 在线问答阶段
1. 查询向量化：将用户问题转换为向量
2. 相似度检索：在向量库中找到最相似的若干文本块
3. Prompt 构建：将用户问题和检索到的上下文组合成完整的 Prompt
4. LLM 生成：调用大语言模型生成基于上下文的回答

## RAG vs 微调（Fine-tuning）

RAG 和微调是两种常见的大模型定制化方案，各有适用场景：

| 对比维度 | RAG | 微调 |
|---------|-----|------|
| 知识更新 | 简单，只需更新文档库 | 复杂，需要重新训练 |
| 实时性 | 高，实时检索最新信息 | 低，训练数据有截止点 |
| 成本 | 较低，主要是向量存储和检索成本 | 较高，训练需要大量计算资源 |
| 数据量需求 | 小，几十篇文档即可起步 | 大，通常需要上千条样本 |
| 可解释性 | 好，可以追溯来源 | 差，模型是黑盒 |
| 风格定制 | 弱，主要改变内容 | 强，可以模仿特定风格 |
| 适用场景 | 知识库问答、文档搜索 | 风格迁移、任务适配 |

## 常用的 RAG 技术栈

### 文档加载
- LangChain Document Loaders
- LlamaIndex Readers
- Unstructured.io

### 文本切分
- Recursive Character Splitter（递归字符切分）
- Semantic Chunking（语义切分）
- Sentence Splitting（句子级切分）

### 向量数据库
- ChromaDB（轻量级，本地持久化）
- Pinecone（云原生，Serverless）
- Weaviate（开源，功能丰富）
- Milvus（高性能，大规模）
- PGVector（基于 PostgreSQL）

### Embedding 模型
- OpenAI text-embedding-3-series
- BGE 系列（智源研究院）
- M3E 系列（阿里云）
- Cohere Embed

### 大语言模型
- GPT-4 系列
- Claude 系列
- 通义千问
- 文心一言
- 各种开源模型（Llama、Qwen、DeepSeek 等）

## RAG 的优化方向

### 基础 RAG（Naive RAG）
最基本的 RAG 实现，即"检索-生成"两阶段。

### 进阶 RAG（Advanced RAG）
在基础 RAG 之上增加了预处理和后处理优化：
- 预检索：查询改写、HyDE、查询扩展
- 检索阶段：多路召回、混合检索
- 后检索：重排序（Reranker）、上下文压缩

### 模块化 RAG（Modular RAG）
将 RAG 拆解为多个可替换的模块，如搜索模块、记忆模块、路由模块等，根据任务需求灵活组合。LangGraph 是模块化 RAG 的典型代表。

## 总结

RAG 是当前企业落地大模型应用的首选方案之一。它以较低的成本解决了大模型的知识时效性和准确性问题，同时保持了良好的可解释性和数据安全性。随着技术的不断发展，RAG 正在从简单的"检索+生成"向更加智能的模块化方向演进。
